This section corresponds to transaction [LAB-102] of the IHE PaLM Technical Framework. Transaction [LAB-102] is used by the Digital Asset Workflow Manager (DAWM) and Physical Asset Workflow Manager (PAWM) actors. It is initiated using `OML^O21` and acknowledged with `ORL^O22`; common segment definitions are specified in the [Volume 2 Appendices](volume-2-appendix.html).

Place Work Order [LAB-102] and Accept Work Order [LAB-103] together form the Additional Work Order Option (Profile Option Identifier `DPOW-WORDER`; see [Volume 1, Section 1:XX.2](volume-1.html#actor-options)). An actor implementing either transaction SHALL implement both.

> **Editor's note:** The section number `3.LAB-102` uses the provisional transaction number as its section identifier pending formal IHE transaction number registration.

### 2:3.LAB-102.1 Scope

This transaction is used by the DAWM to place an order for additional specimen processing to the PAWM. Examples include requests for recuts, additional stains (IHC, FISH), new blocks, or re-coverslipping.

### 2:3.LAB-102.2 Actor Roles

<p id="t3LAB102.2-1" class="tableTitle"><strong>Table 2:3.LAB-102.2-1: Actor Roles</strong></p>

| Actor | Role |
|---|---|
| Digital Asset Workflow Manager (DAWM) | Places a work order on a physical specimen. Acts as order placer. |
| Physical Asset Workflow Manager (PAWM) | Receives the work order and acknowledges receipt. Acts as order filler. |
{: .grid}

### 2:3.LAB-102.3 Referenced Standards

- HL7 v2.5.1: Chapter 4 (OML^O21, ORL^O22), Chapter 7 (SPM segment)

### 2:3.LAB-102.4 Messages

The process flow for this transaction is illustrated in [Volume 1, Use Case #5](volume-1.html#overview) (Work Order).

#### 2:3.LAB-102.4.1 OML^O21 - Place Work Order Message

##### 2:3.LAB-102.4.1.1 Trigger Events

- A pathologist or technologist requests additional work on a physical asset via the DAWM interface.

##### 2:3.LAB-102.4.1.2 Message Semantics

The message is `OML^O21`. MSH-21 SHALL be populated with `DPOW-PLACE-WO^IHE`.

SPM-3 SHALL contain the parent specimen/block ID on which the additional work is requested. SPM-2.1 SHALL be populated with the DAWM-assigned temporary identifier for the expected new asset.

**Field mapping.** Fields this transaction populates (full segment definitions in the [Volume 2 Appendices](volume-2-appendix.html), Appendix A):

| Concept | HL7 Field (v2.5.1) | Usage | Example | Notes |
|---|---|---|---|---|
| Patient ID | PID-3 | R | 1234567890 |  |
| Order control | ORC-1 | R | NW | new work order |
| Requested service | OBR-4 | R | IHC Ki-67 (coded) | technique/test ordered |
| Parent asset ID | SPM-3 | R | B23-17890-A1 | block/specimen the work is on |
| Placer temp asset ID | SPM-2.1 | R | (DAWM temp id) | placeholder for the expected new asset |
{: .grid}

##### 2:3.LAB-102.4.1.3 Expected Actions

The PAWM SHALL register the work order. When the order is fulfilled, the PAWM SHALL send a [LAB-103] Accept Work Order message, followed by a [LAB-100] Physical Asset Registration message for any newly created assets. The PAWM returns the `ORL^O22` acknowledgement described below to indicate receipt.

#### 2:3.LAB-102.4.2 ORL^O22 - Acknowledgement

##### 2:3.LAB-102.4.2.1 Trigger Events

- Receipt of the `OML^O21` Place Work Order message by the PAWM.

##### 2:3.LAB-102.4.2.2 Message Semantics

The PAWM returns `ORL^O22` as the application acknowledgement. If the order is accepted, ORC-1 SHALL be set to `OK` in the `ORL^O22` response; if the order cannot be fulfilled (e.g., insufficient material), ORC-1 SHALL be set to `UA`. MSA-1 conveys the transport-level acknowledgement code (`AA`/`AE`/`AR`); when `AE`/`AR`, an ERR segment SHOULD convey the error detail.

> **Validation required - see WI-DPOW-01.** The exact ORC-1 / MSA / ERR usage is subject to message validation before Trial Implementation.

##### 2:3.LAB-102.4.2.3 Expected Actions

The DAWM SHALL process the acknowledgement and update the order status accordingly. On `AE`/`AR` the DAWM SHOULD surface the failure to the user.

#### 2:3.LAB-102.4.3 CapabilityStatement Resource

Not applicable. DPOW is an HL7 v2.5.1 messaging profile and defines no FHIR CapabilityStatements; actor conformance is defined by the HL7 v2 message and segment specifications above and in the [Volume 2 Appendices](volume-2-appendix.html).

### 2:3.LAB-102.5 Security Considerations

This transaction conveys PHI. All actors SHOULD be grouped with ATNA and the Consistent Time (CT) Time Client (see [Volume 1, Section 1:XX.5](volume-1.html#security-considerations)).

#### 2:3.LAB-102.5.1 Security Audit Considerations

##### 2:3.LAB-102.5.1.1 Digital Asset Workflow Manager (DAWM) Audit

When grouped with an ATNA Secure Node or Secure Application, the DAWM (order placer) SHALL record an audit event when it sends a [LAB-102] message.

##### 2:3.LAB-102.5.1.2 Physical Asset Workflow Manager (PAWM) Audit

When grouped with an ATNA Secure Node or Secure Application, the PAWM (order filler) SHALL record an audit event when it receives a [LAB-102] message.
