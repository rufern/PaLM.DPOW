This section corresponds to transaction [LAB-100] of the IHE PaLM Technical Framework. Transaction [LAB-100] is used by the Physical Asset Workflow Manager (PAWM) and Digital Asset Workflow Manager (DAWM) actors.

All DPOW transactions leverage a constrained profile of HL7 `OML^O21`. The `OML^O21` (Laboratory Order) message initiates each transaction; `ORL^O22` (Laboratory Order Response) is the application acknowledgement. Common segment definitions used by this transaction are specified in the [Volume 2 Appendices](volume-2-appendix.html).

> **Editor's note:** The section number `3.LAB-100` uses the provisional transaction number as its section identifier pending formal IHE transaction number registration.

### 2:3.LAB-100.1 Scope

This transaction is used by the Physical Asset Workflow Manager (PAWM) to register a physical asset (specimen, block, or glass slide) and broadcast its availability and metadata to the Digital Asset Workflow Manager (DAWM). Glass slide registration is supported by every PAWM and DAWM; specimen and block registration apply when the Specimen Registration Option or the Block Registration Option, respectively, is supported (see [Volume 1, Section 1:XX.2](volume-1.html#actor-options)). The type of asset being registered is identified by the MSH-21 profile identifier.

### 2:3.LAB-100.2 Actor Roles

<p id="t3LAB100.2-1" class="tableTitle"><strong>Table 2:3.LAB-100.2-1: Actor Roles</strong></p>

| Actor | Role |
|---|---|
| Physical Asset Workflow Manager (PAWM) | Registers a new physical asset and sends its metadata to the DAWM. Acts as the order placer in the HL7 model. |
| Digital Asset Workflow Manager (DAWM) | Receives physical asset registration. Creates or updates the case-level view. Acts as the order filler in the HL7 model. |
{: .grid}

### 2:3.LAB-100.3 Referenced Standards

- HL7 v2.5.1: Chapter 4 (OML^O21, ORL^O22), Chapter 7 (SPM segment), Chapter 13 (SAC segment)
- Pre-adoptions: SAC-48 (HL7 v2.9.1). See [Significant Changes and Issues](issues.html), Closed Issue 3.

### 2:3.LAB-100.4 Messages

The process flow for this transaction is illustrated in [Volume 1, Use Cases #1-#3](volume-1.html#overview) (specimen, block, and slide registration).

#### 2:3.LAB-100.4.1 OML^O21 - Physical Asset Registration Message

##### 2:3.LAB-100.4.1.1 Trigger Events

- A new physical asset is received and registered in the PAWM: a slide or, when the corresponding option is supported, a specimen or a block.
- Physical asset metadata is updated (e.g., stain applied to a previously unstained slide).
- A physical asset registration is cancelled or corrected.

##### 2:3.LAB-100.4.1.2 Message Semantics

The message is `OML^O21`. MSH-21 Message Profile Identifier SHALL be populated to identify the asset type:

| MSH-21 Value | Asset Type | Volume 1 Option (Profile Option Identifier) |
|---|---|---|
| `DPOW-SPECIMEN^IHE` | Specimen / container registration | Specimen Registration Option (`DPOW-SPECIMEN`) |
| `DPOW-BLOCK^IHE` | Block / cassette registration | Block Registration Option (`DPOW-BLOCK`) |
| `DPOW-SLIDE^IHE` | Glass slide registration | - (required) |
{: .grid}

Every PAWM and DAWM SHALL support [LAB-100] messages with MSH-21 = `DPOW-SLIDE^IHE`. A PAWM or DAWM that supports the Specimen Registration Option (`DPOW-SPECIMEN`) SHALL support [LAB-100] messages with MSH-21 = `DPOW-SPECIMEN^IHE`. A PAWM or DAWM that supports the Block Registration Option (`DPOW-BLOCK`) SHALL support [LAB-100] messages with MSH-21 = `DPOW-BLOCK^IHE`. See [Volume 1, Section 1:XX.2](volume-1.html#actor-options).

ORC-1 Order Control values used in this transaction:

| ORC-1 Value | Meaning |
|---|---|
| NW | New asset registered |
| XO | Update to existing asset metadata |
| CA | Cancellation of asset registration |
{: .grid}

**Specimen-type-specific fields:**

| Asset Type | Option | Key Fields |
|---|---|---|
| Specimen | Specimen Registration Option | SPM-8 (source site, ideally SCT); fixative in OBX-5 (CWE) |
| Block | Block Registration Option | SPM-3 (parent specimen ID); SPM-9 (laterality, ideally SCT); embedding medium in OBX-5 (CWE) |
| Slide | - (required) | SPM-3 (parent block ID); stain in OBX-5 (CWE) when stained; SAC-48 = `WSI` when eligible for scanning |
{: .grid}

> **Note on SPM fields:** SPM-4 SHALL use `TISS` or an appropriate SCT code. Biopsy and similar terms are procedures, not specimen types, and SHALL NOT be used in SPM-4. SPM-8 and SPM-9 SHOULD use SNOMED CT codes (body structure hierarchy and laterality respectively) rather than locally defined codes.

> **Note on OBX-5 for preparation metadata:** Fixative (specimen level), embedding medium (block level), and staining (slide level) SHALL be conveyed in `OBX-5 (CWE)` segments following the SPM segment. This aligns with the approach adopted in DPIA. SPM-6 SHALL NOT be used for this purpose in DPOW.

Full segment definitions are provided in the [Volume 2 Appendices](volume-2-appendix.html) (Appendix A).

##### 2:3.LAB-100.4.1.3 Expected Actions

The DAWM SHALL create or update the appropriate entry (case, block, or slide) for the patient and accession number identified in the message, linked to the parent asset via SPM-3 where applicable. For unstained slides (no OBX stain), the DAWM SHALL create a placeholder entry. When a subsequent update message is received with stain metadata, the DAWM SHALL update the existing placeholder. The DAWM then returns the `ORL^O22` acknowledgement described below.

#### 2:3.LAB-100.4.2 ORL^O22 - Acknowledgement

##### 2:3.LAB-100.4.2.1 Trigger Events

- Receipt of the `OML^O21` Physical Asset Registration message by the DAWM.

##### 2:3.LAB-100.4.2.2 Message Semantics

The DAWM returns `ORL^O22` as the application acknowledgement. MSA-1 conveys the acknowledgement code: `AA` (accept), `AE` (application error), or `AR` (application reject). When MSA-1 is `AE` or `AR`, an ERR segment SHOULD convey the error detail.

> **Validation required - see WI-DPOW-01.** The exact MSA/ERR usage is subject to message validation before Trial Implementation.

##### 2:3.LAB-100.4.2.3 Expected Actions

The PAWM SHALL process the acknowledgement. On `AE`/`AR` the PAWM SHOULD log the failure and MAY retransmit the registration.

#### 2:3.LAB-100.4.3 CapabilityStatement Resource

Not applicable. DPOW is an HL7 v2.5.1 messaging profile and defines no FHIR CapabilityStatements; actor conformance is defined by the HL7 v2 message and segment specifications above and in the [Volume 2 Appendices](volume-2-appendix.html).

### 2:3.LAB-100.5 Security Considerations

This transaction conveys PHI. All actors SHOULD be grouped with ATNA and the Consistent Time (CT) Time Client (see [Volume 1, Section 1:XX.5](volume-1.html#security-considerations)).

#### 2:3.LAB-100.5.1 Security Audit Considerations

##### 2:3.LAB-100.5.1.1 Physical Asset Workflow Manager (PAWM) Audit

When grouped with an ATNA Secure Node or Secure Application, the PAWM SHALL record an audit event when it sends a [LAB-100] message.

##### 2:3.LAB-100.5.1.2 Digital Asset Workflow Manager (DAWM) Audit

When grouped with an ATNA Secure Node or Secure Application, the DAWM SHALL record an audit event when it receives a [LAB-100] message.
