This section corresponds to transaction [LAB-103] of the IHE PaLM Technical Framework. Transaction [LAB-103] is used by the Physical Asset Workflow Manager (PAWM) and Digital Asset Workflow Manager (DAWM) actors. It is initiated using `OML^O21` and acknowledged with `ORL^O22`; common segment definitions are specified in the [Volume 2 Appendices](volume-2-appendix.html).

Place Work Order [LAB-102] and Accept Work Order [LAB-103] together form the Additional Work Order Option (Profile Option Identifier `DPOW-WORDER`; see [Volume 1, Section 1:XX.2](volume-1.html#actor-options)). An actor implementing either transaction SHALL implement both.

> **Editor's note:** The section number `3.LAB-103` uses the provisional transaction number as its section identifier pending formal IHE transaction number registration.

### 2:3.LAB-103.1 Scope

This transaction is used by the PAWM to notify the DAWM that it has accepted and fulfilled a work order placed by the DAWM ([LAB-102]). It is sent once, when the requested work has been carried out. A work order the PAWM cannot accept or fulfil is not answered with [LAB-103]; the rejection is conveyed in the `ORL^O22` acknowledgement to the [LAB-102] request (ORC-1 = `UA`).

### 2:3.LAB-103.2 Actor Roles

<p id="t3LAB103.2-1" class="tableTitle"><strong>Table 2:3.LAB-103.2-1: Actor Roles</strong></p>

| Actor | Role |
|---|---|
| Physical Asset Workflow Manager (PAWM) | Fulfils the work order and sends a response to the DAWM. Acts as order filler. |
| Digital Asset Workflow Manager (DAWM) | Receives the order fulfilment response. Updates the case view accordingly. |
{: .grid}

### 2:3.LAB-103.3 Referenced Standards

- HL7 v2.5.1: Chapter 4 (OML^O21, ORL^O22), Chapter 7 (SPM segment)

### 2:3.LAB-103.4 Messages

The process flow for this transaction is illustrated in [Volume 1, Use Case #5](volume-1.html#overview) (Work Order).

#### 2:3.LAB-103.4.1 OML^O21 - Accept Work Order Message

##### 2:3.LAB-103.4.1.1 Trigger Events

- The PAWM has accepted and fulfilled a work order placed by the DAWM (e.g., the requested slide has been cut and stained).

##### 2:3.LAB-103.4.1.2 Message Semantics

The message is `OML^O21`. MSH-21 SHALL be populated with `DPOW-ACCEPT-WO^IHE`.

ORC-5 SHALL be `CM` (order fulfilled). SPM-2.1 SHALL carry the placer identifier from the [LAB-102] request, and SPM-2.2 SHALL be populated with the PAWM-assigned definitive identifier of the created physical asset.

When the work order results in a new physical asset, a subsequent [LAB-100] Physical Asset Registration message SHALL follow.

> **Note:** [LAB-103] is sent once per work order, upon acceptance and fulfilment. It replaces the separate response transaction considered in earlier drafts (see Closed Issue 2 in [Significant Changes and Issues](issues.html)).

**Field mapping.** Fields this transaction populates (full segment definitions in the [Volume 2 Appendices](volume-2-appendix.html), Appendix A):

| Concept | HL7 Field (v2.5.1) | Usage | Example | Notes |
|---|---|---|---|---|
| Patient ID | PID-3 | R | 1234567890 |  |
| Order status | ORC-5 | R | CM | order accepted and fulfilled |
| Placer asset ID | SPM-2.1 | R | (placer id) | correlates to the LAB-102 request |
| Filler definitive asset ID | SPM-2.2 | R | B23-17890-A2-01 | PAWM-assigned identifier of the created asset |
{: .grid}

##### 2:3.LAB-103.4.1.3 Expected Actions

The DAWM SHALL update the case view to reflect the fulfilled work order and SHALL await the associated [LAB-100] message for the newly created asset. The DAWM then returns the `ORL^O22` acknowledgement described below.

#### 2:3.LAB-103.4.2 ORL^O22 - Acknowledgement

##### 2:3.LAB-103.4.2.1 Trigger Events

- Receipt of the `OML^O21` Accept Work Order message by the DAWM.

##### 2:3.LAB-103.4.2.2 Message Semantics

The DAWM returns `ORL^O22` as the application acknowledgement. MSA-1 conveys the acknowledgement code: `AA` (accept), `AE` (application error), or `AR` (application reject). When MSA-1 is `AE` or `AR`, an ERR segment SHOULD convey the error detail.

##### 2:3.LAB-103.4.2.3 Expected Actions

The PAWM SHALL process the acknowledgement. On `AE`/`AR` the PAWM SHOULD log the failure and MAY retransmit the response.

#### 2:3.LAB-103.4.3 CapabilityStatement Resource

Not applicable. DPOW is an HL7 v2.5.1 messaging profile and defines no FHIR CapabilityStatements; actor conformance is defined by the HL7 v2 message and segment specifications above and in the [Volume 2 Appendices](volume-2-appendix.html).

### 2:3.LAB-103.5 Security Considerations

This transaction conveys PHI. All actors SHOULD be grouped with ATNA and the Consistent Time (CT) Time Client (see [Volume 1, Section 1:XX.5](volume-1.html#security-considerations)).

#### 2:3.LAB-103.5.1 Security Audit Considerations

##### 2:3.LAB-103.5.1.1 Physical Asset Workflow Manager (PAWM) Audit

When grouped with an ATNA Secure Node or Secure Application, the PAWM (order filler) SHALL record an audit event when it sends a [LAB-103] message.

##### 2:3.LAB-103.5.1.2 Digital Asset Workflow Manager (DAWM) Audit

When grouped with an ATNA Secure Node or Secure Application, the DAWM (order placer) SHALL record an audit event when it receives a [LAB-103] message.
